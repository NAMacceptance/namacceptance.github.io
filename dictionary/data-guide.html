01

How the database works

Each row represents one TSAR-listed test method. The dashboard keeps the original source information visible, then adds documented fields for consistent description and analysis.

1

Source snapshot

Identifiers, titles, topics, workflow text and public descriptions are retained from TSAR.

2

Transparent derivation

Parsing and rule-based classifications generate comparable pathway, endpoint and methodology variables.

3

Review and provenance

Procedural fields record review status, dates, lineage and verification context separately from the scientific variables.

4

Reusable analysis

Controlled vocabularies and binary indicators support reproducible filtering, counts and figures.

02

Read the variable class first

The updated codebook makes the origin of every variable explicit. A review label does not change a variable’s creation class.

SRC

Source-reported

Copied from TSAR or another identified source without substantive transformation.

DDV

Deterministically derived

Created by a specified parse, lookup, split, aggregation or logical recoding.

RBV

Rule-based text-derived

Created from predefined keyword rules, dictionaries or regular expressions.

LLMV

LLM-derived/search-based

Created through documented AI-assisted extraction, synthesis or classification.

PRV

Procedural

Records processing, audit, verification or study-workflow information rather than a method property.

05

What the updated codebook adds

The latest workbook is FAIR-aware: every documented variable has more than a definition. It also tells you how to interpret and validate the stored value.

Allowed value / format

Shows the literal representation that can appear in the data, including stable codes and list formats.

Input and derivation

Records the source field(s) and transformation logic used to create a derived value.

Data type and missingness

States whether a value is text, date, integer or a controlled list, and how blanks or legacy values should be read.

Vocabulary and validation

Links categorical fields to their controlled vocabulary or validation rule so categories remain stable across releases.

Recommended use / caution

Explains when a field is suitable for analysis and where it may hide source detail or require review.

Provenance

Distinguishes source, deterministic, rule-based, AI-assisted and procedural values for transparent reuse.

06

Important interpretation rules

These rules prevent common misreadings when filtering, counting or comparing methods.

Totals can exceed 147

Endpoint, methodology and bottleneck variables can be multi-label; one method can contribute to several labels.

Status is not quality

Regulatory status describes position in a pathway, not the scientific quality or usefulness of a method.

Keep the raw field

Use x_topic and step_stage when you need the original TSAR wording behind a derived classification.

Legacy values matter

A legacy 99 represents unavailable source information; do not silently convert it into a negative result.

Review and lifecycle are separate

All 147 methods are expert reviewed. The live TSAR lifecycle was checked for 40 methods; the other 107 retain the original export position. Neither flag is a quality score.
